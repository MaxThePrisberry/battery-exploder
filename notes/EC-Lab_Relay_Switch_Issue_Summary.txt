EC-LAB RELAY SWITCHING ISSUE - WORK SUMMARY (2025-11-10)
=============================================================================

PROBLEM STATEMENT
-----------------
During temperature ramp experiments, OCV/GEIS measurements fail immediately
after relay switching with error -2147417842 (0x8001010E = RPC_E_DISCONNECTED).

The same measurements work perfectly when run standalone (outside of ramp
experiments), so the issue is specifically related to the relay switching
operation.


ROOT CAUSE ANALYSIS
-------------------
Through comprehensive debug logging (commit 421500e), we discovered:

1. After relay switching, EC-Lab TestConnection returns:
   - Error: ECLAB_ERR_NOT_CONNECTED (-2107)
   - Message: "Device 0 is not connected"
   - This persists even after 3+ seconds

2. Once EC-Lab believes device is disconnected, ALL method calls fail:
   - StopChannel: RPC_E_DISCONNECTED (0x8001010E)
   - LoadSettings: RPC_E_DISCONNECTED (0x8001010E)

3. EC-Lab detects the physical relay disconnection and marks the device
   as "not connected" internally, invalidating all COM interface calls.

KEY INSIGHT: This is NOT a COM transport issue or channel state issue.
EC-Lab is detecting the hardware disconnection and invalidating the device.


ATTEMPTED SOLUTION (COMMIT 91e4dc6)
-----------------------------------
Added reconnect logic to SwitchToBioLogic():
1. Call ECLAB_DisconnectDevice() to clear fault state
2. Wait 0.5 seconds
3. Call ECLAB_ConnectDevice() to reconnect
4. Verify with TestConnection()

RESULT: Failed with new error sequence (log 2025-11-10-6.txt lines 302-307):
- Line 304: DisconnectDevice failed (returned -2147417842)
- Line 305: Disconnect returned: -2102 (ECLAB_ERR_COM_INVOKE_FAILED)
- Line 306: ConnectDevice failed with -2108 (ECLAB_ERR_ALREADY_CONNECTED)

ANALYSIS:
- DisconnectDevice fails because device is already in "not connected" state
- When disconnect fails, conn->isConnected flag remains TRUE
- ConnectDevice checks isConnected flag and returns ALREADY_CONNECTED error
- Net result: We're stuck unable to reconnect


PROPOSED SOLUTIONS FOR TOMORROW
--------------------------------
Option 1: Force reset the isConnected flag
   - After DisconnectDevice fails, manually set conn->isConnected = false
   - This allows ConnectDevice to proceed even if disconnect failed
   - Modify exp_temp_ramp.c to handle the disconnect failure gracefully

Option 2: Skip disconnect entirely
   - Don't call DisconnectDevice at all
   - Force conn->isConnected = false directly before calling ConnectDevice
   - Rationale: If EC-Lab thinks device is disconnected, calling
     DisconnectDevice is redundant

Option 3: Use lower-level COM reconnection
   - Release and recreate the IEClabExe COM interface
   - This is more invasive but might be necessary
   - Would require modifications to eclab_olecom.c

Option 4: Add "force reconnect" function
   - Create ECLAB_ForceReconnect() that:
     a) Forces conn->isConnected = false
     b) Calls ConnectDevice()
   - This is cleaner than modifying flags from outside

RECOMMENDED: Try Option 4 first (cleanest), then Option 2 if needed.

- The issue ONLY occurs during temperature ramp experiments
- Relay switching involves:
  1. Disconnect PSB relay (TNY_PSB_PIN)

  3. Connect BioLogic relay (TNY_BIOLOGIC_PIN)

- After experiment cleanup, subsequent standalone OCV works again
- This suggests something in experiment cleanup resets EC-Lab's state
